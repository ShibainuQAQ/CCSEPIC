# 常见问题（FAQ）

按"症状 → 原因 → 怎么办"组织。**这些都是本项目真实踩过的坑**，不是推测。

---

## 串口与通信

### Q1. 脚本报 `[FAIL] 没找到 STM32`
先看它有没有打印**"串口被占用：COM11"** —— 这通常意味着**手动控制台没退出**（`manual_tool` 握着串口，别的工具就打不开）。
→ 在手动台里按 `x` 退出，再跑。

如果打印的是"探测无应答"，则是板子/接线问题：检查 USB-TTL 的 TXD→PA10、RXD→PA9、GND→GND、BOOT0=0，
以及 `python hw_bridge/tools/port_probe.py --list` 能不能看到 CH340。

### Q2. 昨天还好好的，今天串口号变了
**USB 口号本来就会变**。本项目调试期间就漂过：STM32 `COM14 → COM11`、K210 `COM5 → COM15`。
→ 上层脚本已改成**自动认口**（STM32 用 `PING` 探测、K210 找 CanMV 提示符），一般不用管；
底层工具（`step_test.py`、`port_probe.py`）需要手动 `--port`。

### Q3. 一开串口，板子就复位、位置归零、电机松了
**这是硬件设计如此**：USB-TTL 的 DTR/RTS 接到了 STM32 复位脚。
→ 所以**长动作序列必须在"一次打开串口"期间发完**（本项目所有工具都是这么写的）；
→ 每次开串口后重新 `EN 1` + `ZERO all` 属正常流程，不是故障。

### Q4. 发命令回 `ERR 11 / ERR 12 / ERR 14 / ERR 16`
这是固件的**安全门禁**在拦（详见 `hw_bridge/protocol.md` 错误码表）：

| 错误 | 含义 | 怎么办 |
|---|---|---|
| `ERR 11 not homed` | 还没"声明自己在哪" | 发 `ZERO all`（把当前位置定义为 0） |
| `ERR 12 soft limit` | 目标超出软限位 | `ZERO` 或 `LIM off` |
| `ERR 14 estopped` | 急停态 | 发 `CLEAR` |
| `ERR 16 not enabled` | 驱动器没使能 | 发 `EN 1` |
| `ERR 15 axis busy` | 上一段还没走完 | 等它停，或 `STOP` |

## 电机 / 机构

### Q5. 某个轴完全不动，但位置计数在涨
⚠️ **"计数在涨"不代表引脚在发脉冲** —— 位置是软件累加的，引脚配置错了照样涨。
排查顺序（从便宜到贵）：

1. 手动台按 **`M`**：看 `EN 引脚`（PA4/PA7 是否"使能"）、`acrl/acrh`（PUL/DIR/EN 是否配成推挽输出）。
2. 看驱动器 **OLED**：菜单里必须是 **模式=脉冲 / 细分=16 / 电流 500~800 mA**；有报警码先查编码器插头。
3. 万用表：手动台按 **`T`**（20 Hz 连发 20 秒）→ 量 **PUL 脚 ↔ GND** 有没有频率（正常速度只发 0.1 秒，表测不到）。
4. 量驱动器的 **`Com` ↔ 电源 GND 是否导通**：X42 排针只有 `V G Com En Stp Dir`，**共阴接法全靠这一根**，漏接则三路光耦全不导通（电机既不动也不锁）。
5. 换线/换驱动器交叉验证。

**本项目实例**：Y 轴"计数在涨、电机不动、`acrl` 正常" → 最终判定 **PA5 引脚损坏**，固件 v0.8.2 起把 Y 脉冲改到 **PA12**
（`09_固件/src/board.c` 的 `STEP_Y_PUL_PIN`，改这个数即可换回/再换）。

### Q6. 舵机持续嗡嗡响、发热
**顶到内部止挡了**。Z 轴越接近 611 µs 越贴止挡（本项目为此烧过一颗舵机）。
→ 听到嗡嗡就往回收 20~30 µs；夹爪同理别一直顶死。

### Q7. 舵机动作明显变慢/不到位
MG996R 堵转电流 ≈2.5 A。先查**独立舵机电源**（5.5~6 V / ≥3 A、并 470~1000 µF 电容），再查机构是否卡滞。
舵机**没有位置反馈**，脚本只能按固定延时等到位，所以"延时突然不够用"往往就是供电或卡滞。

## 视觉与坐标

### Q8. 脚本报"8 步完成"，但货根本没被夹起来
**舵机无反馈 + 步进开环** ⇒ 脚本只能保证"动作都发出去了"，**不知道夹住没有**。
→ 必须**动作后复拍一张**核验（`vision_pick.py --color any --dry`，看列表里那件货是否消失）。
本项目实测过两种"抓空"：
1. 货在画面**最边缘被裁掉** ⇒ 质心偏向内侧 ⇒ 爪子对不准 ⇒ 把货推走 10 余毫米；
2. **Z 落点**与该货物高度不匹配 ⇒ 爪子从旁边/下面过去 ⇒ 也是推。

### Q9. 识别出的坐标整体偏了 / 抓偏
按可能性排序：
1. **相机被动过** ⇒ 需要重测比例+旋转：`python 08_视觉/vision/calibrate_2point.py --dist -40`；
2. **Z 高度变了** ⇒ 相机挂在 Z 升降台上，**Z 一降，mm/px 就变** ✗ ⇒ 拍照与抓取时 Z 必须在最高（脚本已保证，手动降过要记得抬回）；
3. **起点不是你以为的原点** ⇒ 脚本每次启动都把"当时夹爪位置"定为 (0,0)，跑之前先确认机构停在你要的原点。

### Q10. 形状判据在 `hexagon / poly7x / circle / square-ish` 之间跳
旧判据用 `approxPolyDP` **数顶点**，对光照/抗锯齿的一两个像素太敏感。
现已改为**角向对称阶数**（凸包上按"射线-边求交"取半径 → FFT 看几重对称）+ **椭圆残差**，
在实验室照片上三件货都能稳定区分（`08_视觉/vision/shape_probe.py` 可打印每件的谐波/残差数值来标阈值）。
⚠️ **真实光照 + 塑料反光下仍会偶发跳变** —— 所以生产用法是**按颜色选件**（现场一色一件最稳），
形状判据用于分盒前复核。下一步修复方向：相机俯角下的**仿射白化**后再做对称性分析。

### Q11. 标定脚本报"两图里找不到同一件货"
`calibrate_2point.py` 要**画面里有一件货**，让龙门走 40 mm 后同一件货的像素位移足够大。
→ 摆一件货在画面中间；位移太小就换 `--dist`（只能为负，因为安全位就是 +X 极限）。

## 环境 / 工具

### Q12. `flash_keil.ps1` 报"未对文件进行数字签名"
Windows 执行策略拦截。→ 加参数运行：
```powershell
powershell -ExecutionPolicy Bypass -File 09_固件\flash_keil.ps1
```

### Q13. `pip install opencv-python` 很慢或失败
换镜像：
```bash
pip install -r hw_bridge/requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### Q14. `09_固件/build.py` 报找不到编译器
它调用 Keil 自带的 `armclang`，路径写死在脚本顶部 `KEIL_BIN`。→ 改成你机器上的实际路径；
并确认装了 Keil 器件包 `Keil.STM32F1xx_DFP`。

### Q15. 仓库里的 `hw_bridge/vendor/` 哪去了？
**已从版本库移除**（原来是把 pyserial 等库原样复制入库，约 1260 个第三方文件）。
现在用 `hw_bridge/requirements.txt` 安装。脚本里的 `sys.path.insert(".../vendor")` 仍保留：
本地若有该目录就优先用，没有则退回 pip 安装的版本，两者都能跑。
