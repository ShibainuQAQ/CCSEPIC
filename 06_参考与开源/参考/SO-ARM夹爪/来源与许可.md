### 本机为什么必须走镜像 + Python

| 通道 | 结果 |
|---|---|
| `github.com` / `raw.githubusercontent.com` 直连 | ❌ 失败（本机网络不通） |
| `git clone` / `curl.exe`（走 Windows schannel） | ❌ `SEC_E_NO_CREDENTIALS (0x8009030E)` —— 沙箱环境没有可用凭据，**跟镜像无关，换哪个地址都一样** |
| `raw.gitmirror.com` | ❌ DNS 解析失败 |
| jsDelivr（`cdn.jsdelivr.net`） | ❌ 仓库 >50MB，整体被拒（`Package size exceeded the configured limit of 50 MB`） |
| **`ghproxy.net` + Python（自带 OpenSSL）** | ✅ 可用 —— 所以下载脚本用 `urllib` 而不是 curl/git |

> 复现：`python "参考\SO-ARM夹爪\_fetch.py" curated`（脚本里写死了镜像与文件清单）

## 4. ⚠️ 使用红线（三条，联赛规则）

1. **不要把它的 STL 直接打印出来当我们的夹爪。** 工创赛规则：**禁止成品套件拼装、非标件须自主设计制造**；且 A2 创意由专家打分、**同校外形雷同全 0**。→ 正确姿势：**只借构型（齿条同步 + 导杆轴承导向 + 平行自定心），按我们自己的货物/储物盒尺寸重新建模**（我方版本见 `夹爪设计参数表.md`，机构、行程、驱动舵机、尺寸全都不同）。
2. **它的文档与图片是 CC BY 4.0，用了就得署名** —— 与我们"提交件匿名"的纪律直接冲突。→ **说明书第 8 节图 3（Z 升降连杆与夹爪机构图）必须自己画**；它的装配图/规格图只能在队内看，别放进任何提交件。
3. **署名只留在队内**（即本文件夹）。这与 `开源\` 四篇（西安理工，CC BY-NC-SA）的处理方式一致：提交件里把工程实践写成"我们的设计决策"，来源只在队内账上。

> 若将来确实要复用它的某个零件几何（目前没有这个必要），必须随件附 `HARDWARE-LICENSE.txt` 并在队内记明来源 —— **不要让它出现在匿名提交件里**。

### ⚠️ 两个已知坑

1. **`models\README.md` 没提 STEP，但仓库里其实有**（`models\RB9.01.062.000 Gripper.STEP`，5.7MB）—— 队内要用 Fusion 量真实齿数/模数，直接开它，别只看 README。
2. **`_measure.py --teeth` 的齿数/模数判读不可靠**（2026-09-16 试了"数齿顶平台""圆心网格搜索+穿越计数""按全齿高反推""自相关求节距"四版算法，都被 STL 顶点稀疏 + 零件带轮毂/凸台带偏）。**包围盒是可靠的，齿数请以 Fusion 打开 STEP 实量为准** —— 我方设计不依赖它的齿数（我们按自己的行程定 M1.5/z14）。
