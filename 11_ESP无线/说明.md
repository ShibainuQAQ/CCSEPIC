## 1. 架构与角色

| 环节 | 谁 | 说明 |
|---|---|---|
| 电脑 | 笔记本 | 用 **USB 串口**跟 C3 说话；**WiFi 保持联网**（要调云端 AI），所以不占 WiFi |
| 电脑侧 | **ESP32-C3** | `COM7`；**STA** 加入 C6 的热点 + **TCP 客户端**；把 USB 串口与 TCP 互相透传 |
| 空中 | WiFi | SSID **`SORT-C6`**（开放）、**信道 1**、TCP 端口 **3333** |
| 装置侧 | **ESP32-C6** | **AP** + **TCP 服务端** + **UART1 透传** |
| 单片机 | STM32F103RCT6 | 接 C6 的 **UART1**：`GPIO4`(C6 TX) → `PA3`(USART2_RX)、`GPIO5`(C6 RX) ← `PA2`(USART2_TX)、**GND 共地** |

> ⚠️ **为什么用 UART1 而不是 UART0**：`GPIO16/17`(=UART0) 被板载 USB-转串口桥片（CH340K）占着当调试口；
> 拿它接 STM32 会和桥片的 TXD 顶牛（两个 3.3V 输出对驱）。所以 STM32 挂 **UART1**。

## 2. 硬件与端口

| 角色 | 板子 | 端口 | 识别特征 |
|---|---|---|---|
| 电脑侧 | **ESP32-C3** | `COM7` | **`303A:1001`** = 乐鑫**原生 USB-Serial-JTAG**（不是 CH340）；MAC `E4:B0:63:22:C4:C4` |
| 装置侧 | **ESP32-C6** | `COM8` | **`1A86:7522` = CH340K**（走板上的 **UART 口**那个 USB-C）；MAC `E8:F6:0A:F6:14:5D` |

⚠️ **CH340K 撞车提醒**：C6 的桥片和 **STM32 板**是**同一颗 CH340K、同一个 VID:PID、都没有序列号** ——
两个一起插时**名字完全一样**，只能靠 COM 号区分（或拔一个看谁消失）。建议**固定插孔**。

**ESP32-C6 板上的两个 USB-C 口**：
- **`UART` 口** ✅ 用它 —— 桥片独立于芯片，**ESP32 复位时 COM 号不变**（我们每次连板子都会复位它，这点很关键）；
- **`OTG` 口**（原生 USB）—— 免驱、也能刷，但**芯片一复位就重新枚举**，脚本容易扑空。缺桥片驱动时才用它顶一下。

## 4. 刷写流程

```powershell
# ① 先备份（只对 C6 需要，出厂固件留个后路）
& 'D:\python\python.exe' -m esptool --port COM8 --baud 460800 read_flash 0 0x800000 11_ESP无线\firmware\c6_factory_demo_backup_8MB.bin
# ② 擦
& 'D:\python\python.exe' -m esptool --chip esp32c6 --port COM8 erase_flash
# ③ 刷
& 'D:\python\python.exe' -m esptool --chip esp32c6 --port COM8 --baud 460800 write_flash -z 0x0 11_ESP无线\firmware\ESP32_GENERIC_C6-20260824-v1.29.0.bin
```

- ⚠️ **必须先 `erase_flash`**：只 `write_flash` 会留下旧的 LittleFS 分区 → 开机刷屏
  `The filesystem appears to be corrupted …`（实测踩到过，全擦后一次就好）。
- ⚠️ **读/写不要用 921600**：CH340K 在这个速率下会 `Packet content transfer stopped`（实测 8MB 读到 65% 断），**460800 稳定**。
- 刷完不按 BOOT：原生 USB / 桥片都能自动进下载模式；esptool 自己会处理。
- 成功判据：串口出现 `MicroPython v1.29.0 on 2026-08-24; ESP32C3/C6 module with …` + `>>>`。
- **还原出厂固件**：`write_flash -z 0x0 c6_factory_demo_backup_8MB.bin`

### 6.2 UART1 硬回环闭环（2026-10-01，`GPIO4` 与 `GPIO5` 用杜邦线短接）

把 `MIRROR_TO_CLIENT` 关掉之后，**回程数据只可能来自那根短接线**，于是这条测试能把"UART1 通不通"焊死：

PC 侧（`COM7`）：

```
TX 21 B: LOOPBACK-TEST-12345\r\n
RX 21 B: LOOPBACK-TEST-12345\r\n        ← 一字不差，且**没有** <mirror> 前缀
```

C6 侧：

```
[C6] MIRROR_TO_CLIENT=False
[C6] TCP->UART 21 B (total 21): b'LOOPBACK-TEST-12345\r\n'   ← TCP 进 → 写进 UART1(GPIO4)
[C6] UART->TCP 16 B (total 16): b'LOOPBACK-TEST-12'          ← 从 UART1(GPIO5) 收回
[C6] UART->TCP  5 B (total 21): b'345\r\n'                   ← 合计 21 B，与发出完全一致
```

⇒ **"笔记本 → C3 → 无线 → C6 → UART1 出 → 线 → UART1 回 → C6 → 无线 → C3 → 笔记本"整圈打通**。
把短接线换成 STM32 的 `PA3/PA2`，这条链就直接服务分拣主控了。

## 7. ⚠️ 踩坑清单（按踩到的顺序，都很隐蔽）

| # | 现象 | 真因 | 处理 |
|---|---|---|---|
| 1 | 板子一开机刷屏 `partition 0 invalid magic number` / `filesystem corrupted` | 只 `write_flash` 没 `erase_flash`，旧文件系统残留 | **先擦后刷** |
| 2 | `main.py` 一跑就 `AttributeError: 'TextIOWrapper' object has no attribute 'flush'` | 这个构建的 `sys.stdout` **没有 `flush()`** | flush 一律包 `try/except` |
| 3 | **C3 扫得到热点（-40dBm）却连不上**：status 一路 `CONNECTING→IDLE`、`isconnected()` 恒 False | **`ap.ifconfig((静态IP…))` 在 ESP32-C6 上抛 `Wifi Unknown Error 0x5001`，并把软 AP 的 DHCP 服务搞停** → 客户端**能关联但永远拿不到 IP** | **别调 `ap.ifconfig`**；AP 默认 `192.168.4.1` + 自带 DHCP。要静态 IP 在**客户端**设 |
| 4 | 偶发 `OSError: Wifi Internal State Error` | STA 还记着**已经消失的旧热点** | `active(False)` → 停 0.6s → `active(True)` 彻底复位射频 |
| 5 | 两块板贴在一起时信号 **-6 dBm**（过热） | 20dBm 发射 + 距离几厘米 = 接收端可能饱和 | `ap.config(txpower=2.0)`，两端都压功率；装置装好后可调回 8~20 |
| 6 | 回传里 `<mirror>` **每字节出现一次** | C3 侧 `read(1)` 就 `send` → **一个字节一个 TCP 包** | 一次 poll 到就把**当前可读的全部取走**再发（实测：整行 14B 合成 1 包） |
| 7 | 批量读改成 `if poller.poll(0):` 当判据后，**整条桥卡死、一个字节都发不出** | `poll(0)` 把 **socket 的事件**也算进来了 → 没有更多 USB 字节时继续 `read(1)` **阻塞** | 判据必须是"**只有 stdin 可读**"：`for obj,ev in poller.poll(0): if obj is sys.stdin and ev & POLLIN`（已封装成 `stdin_ready()`） |

**排查心法（本次最有价值的一招）**：
在 AP 那侧打印 **`ap.status("stations")`** —— 它直接告诉你"客户端到底有没有关联上"。
本次就是靠 `stations=[(b'\xe4\xb0c"\xc4\xc4', '192.168.4.2')]` 一句话把范围从"C3 连不上"缩到"**C3 连上了、是拿不到 IP**"。
**"关联"与"拿到 IP"是两件事，中间隔着 DHCP。**
